1. Jelaskan mengapa kita menggunakan `ModelForm` pada Django alih-alih membuat form HTML secara manual. Selain itu, jelaskan pula mengapa kita diwajibkan menambahkan `{% csrf_token %}` pada form tersebut!

`ModelForm` digunakan pada Django karena dapat menghubungkan form secara langsung dengan model yang digunakan dalam aplikasi. Jika form dibuat secara manual dengan HTML, kita perlu menentukan sendiri setiap input, menyesuaikan nama field dengan model, mengambil data dari request, melakukan validasi, dan menuliskan proses untuk menyimpan data ke database. Dengan menggunakan `ModelForm`, Django dapat membuat form berdasarkan field yang sudah didefinisikan pada model sehingga proses tersebut menjadi lebih sederhana dan terstruktur. Selain itu, `ModelForm` juga menyediakan mekanisme validasi yang dapat memastikan data yang dimasukkan sesuai dengan aturan field pada model sebelum data disimpan. Pada proyek portofolio ini, saya menggunakan `ExperienceForm` yang merepresentasikan model `Experience`. Model tersebut memiliki beberapa field seperti `title`, `description`, `category`, `thumbnail`, `started_at`, `ended_at`, `role`, `is_featured`, dan `display_order`. Field-field yang perlu diisi oleh pengguna dapat ditampilkan melalui `ExperienceForm`, sedangkan field seperti `id` tidak perlu dibuat sebagai input karena dikelola oleh Django. Penggunaan `ModelForm` juga mempermudah implementasi fitur Create dan Update yang dibuat pada halaman Experience. Pada proses Create, form digunakan tanpa instance sehingga data yang valid akan disimpan sebagai object Experience baru. Pada proses Update, form diberikan `instance` dari Experience yang ingin diubah sehingga data yang sudah ada dapat ditampilkan kembali pada form dan kemudian diperbarui ketika pengguna melakukan submit. Setelah form valid, data dapat disimpan menggunakan `form.save()`. Penggunaan `ModelForm` membuat implementasi form menjadi lebih ringkas, terintegrasi dengan model, dan mengurangi kebutuhan untuk menulis proses pengolahan data secara manual.

Selain menggunakan `ModelForm`, form yang melakukan request dengan method `POST` juga perlu menggunakan `{% csrf_token %}`. CSRF atau Cross-Site Request Forgery merupakan salah satu jenis serangan yang dapat membuat pengguna yang sedang memiliki sesi aktif pada suatu website mengirimkan request yang tidak diinginkan ke website tersebut. Django menyediakan CSRF token untuk membantu memastikan bahwa request yang melakukan perubahan data berasal dari form yang sah dari aplikasi. Pada proyek ini, token tersebut digunakan pada form Create, Update, dan Delete karena ketiganya melakukan perubahan terhadap data pada database. Ketika form dikirim, Django akan memeriksa keberadaan dan validitas token tersebut. Jika token tidak ada atau tidak sesuai, Django dapat menolak request yang diterima. Oleh karena itu, `{% csrf_token %}` merupakan mekanisme keamanan yang penting untuk melindungi operasi mengubah data dari request dari sumber lain yang tidak sah.

2. Pada Tutorial 03, kita membahas format data JSON dan XML. Mengapa JSON lebih disukai dalam pengembangan aplikasi web modern dibandingkan XML?

JSON (JavaScript Object Notation) adalah salah satu format yang digunakan untuk pertukaran data antara aplikasi, khususnya dalam pengembangan aplikasi web. JSON lebih banyak digunakan dalam aplikasi web modern dibandingkan XML karena struktur penulisannya relatif lebih sederhana dan ringkas. JSON menggunakan pasangan key dan value serta struktur object dan array yang umum digunakan dalam pemrograman. Hal ini membuat data JSON relatif mudah dibaca oleh manusia sekaligus mudah diproses oleh program. Contohnya, informasi sebuah experience dapat direpresentasikan sebagai object yang memiliki data seperti `title`, `category`, dan `role`. Pada XML, data yang sama membutuhkan tag pembuka dan penutup untuk setiap informasi sehingga struktur yang dihasilkan dapat menjadi lebih panjang. JSON juga didukung oleh berbagai bahasa pemrograman sehingga tidak terbatas pada JavaScript saja. Bahasa seperti Python juga dapat membaca dan memproses JSON, sehingga JSON sesuai digunakan ketika server dan client menggunakan teknologi yang berbeda.

JSON juga sangat sesuai digunakan dalam komunikasi antara client dan server karena data dapat dikirim tanpa harus mengirimkan keseluruhan struktur halaman HTML. Client biasanya hanya membutuhkan data yang kemudian dapat diproses atau ditampilkan sesuai kebutuhan, sehingga hal ini penting dalam pengembangan API. Dalam proyek portofolio ini, data Experience dibuat tersedia dalam format JSON melalui sebuah endpoint. View mengambil data Experience dari database, melakukan serialization, kemudian mengembalikan hasilnya sebagai response dengan `content_type="application/json"`. Dengan adanya endpoint tersebut, data Experience tersedia dalam bentuk tampilan pada halaman web dan dapat disediakan sebagai data terstruktur yang dapat dibaca dan diproses oleh client atau aplikasi lain. Oleh karena itu, JSON menjadi format yang sesuai untuk kebutuhan data delivery pada proyek ini karena lebih sederhana, ringkas, mudah diproses, dan cocok digunakan untuk komunikasi antara server dan client.

3. Jelaskan alur yang terjadi saat kamu menggunakan fungsi view untuk mengembalikan data portofoliomu dalam bentuk JSON. Mengapa kita perlu melakukan proses serialization pada model Django sebelum datanya dikembalikan?

Ketika view digunakan untuk mengembalikan data portofolio dalam bentuk JSON, terdapat beberapa tahap yang terjadi mulai dari pengambilan data dari database sampai data tersebut diterima oleh client. Pada proyek ini, proses tersebut diterapkan pada data Experience melalui fungsi `get_experiences_json()`. Ketika endpoint JSON diakses, request akan diarahkan ke view tersebut. View kemudian mengambil seluruh data Experience menggunakan `Experience.objects.all()`. Perintah tersebut menggunakan Django ORM untuk mengambil data dari database dan menghasilkan QuerySet yang berisi object-object dari model `Experience`. Data yang diperoleh pada tahap ini masih berupa object Django sehingga belum dapat langsung dikirim sebagai JSON response.

Oleh karena itu, data tersebut kemudian perlu melalui proses serialization menggunakan `serializers.serialize("json", experiences)`. Serialization adalah proses mengubah object atau QuerySet Django menjadi representasi data dalam format tertentu, dalam kasus ini JSON. Proses ini memungkinkan data dari object Django untuk dikirim melalui HTTP sebagai data yang dapat dibaca dan diproses oleh client. Hasil serialization pada model `Experience` mencakup informasi mengenai model dan primary key serta field-field yang terdapat pada setiap object. Field yang ikut direpresentasikan antara lain `title`, `description`, `category`, `thumbnail`, `started_at`, `ended_at`, `role`, `is_featured`, dan `display_order`. Setelah proses serialization selesai, hasilnya dikembalikan menggunakan `HttpResponse` dengan `content_type="application/json"`. Pengaturan tersebut memberi informasi kepada client bahwa response yang diterima merupakan data JSON.

Pada proyek ini, JSON tersebut disediakan sebagai endpoint dan juga dapat digunakan kembali ketika halaman Experience ditampilkan. Fungsi `show_experience()` memanggil `get_experiences_json()` untuk memperoleh data dalam bentuk JSON. Setelah mendapatkan response tersebut, isi JSON dibaca menggunakan `json_response.content.decode("utf-8")` dan kemudian dilakukan proses deserialization menggunakan `serializers.deserialize("json", ...)`. Deserialization merupakan proses kebalikan dari serialization, yaitu mengubah data JSON kembali menjadi object Django. Object hasil deserialization kemudian dikumpulkan ke dalam sebuah list dan dapat diproses kembali, misalnya diurutkan berdasarkan tanggal mulai experience. Setelah itu, data tersebut dimasukkan ke dalam context dengan nama `experience_list` dan dikirim ke template `experience.html`. Template kemudian menggunakan data tersebut untuk menampilkan daftar experience pada halaman web.

Serialization diperlukan karena object Django yang diperoleh dari database tidak dapat langsung dikirim sebagai JSON. Object tersebut masih memiliki struktur internal sebagai object Python/Django, sedangkan JSON merupakan format data yang dapat digunakan untuk pertukaran informasi melalui HTTP. Dengan melakukan serialization, data dari database dapat diubah menjadi format yang lebih umum dan dapat dipahami oleh client maupun sistem lain. Sebaliknya, ketika data JSON perlu digunakan kembali sebagai object Django dalam aplikasi, proses deserialization dapat dilakukan. Pada implementasi proyek ini, alurnya menjadi database, kemudian QuerySet dari `Experience.objects.all()`, dilanjutkan dengan serialization menjadi JSON, pengiriman JSON melalui `HttpResponse`, kemudian deserialization kembali menjadi object Django, dan akhirnya data digunakan untuk menghasilkan tampilan pada halaman Experience. Proses tersebut menunjukkan bagaimana data yang tersimpan pada model Django dapat disediakan dalam format JSON sekaligus digunakan kembali untuk menampilkan data pada halaman web.
